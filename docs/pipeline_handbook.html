1.4 The one-paragraph summary of the configuration

Source audio is separated into vocals and backing with HTDemucs. Speakers are found with pyannote segmentation. The transcript comes from Gemini 3.7 Flash through an OpenAI-compatible proxy. Word-level times come from Google Chirp 3 in the us multi-region, with Chirp 2 as fallback. Those times are then overruled by forced alignment (Meta MMS_FA, 29-symbol label set, star tokens on) in a window bounded by trusted neighbours — fa_then_chirp. A Theil-Sen drift guard reverts any run of lines that walks away from the trend. The timeline is resolved by trimming earlier ends rather than moving later starts, line onsets are snapped to real speech using a 300–3400 Hz band-limited gate on the vocals stem, and ends are extended into following pauses by at most 0.30 s. Voices are cloned per speaker with per-line references where available. The per-line source-language leak detector is OFF, which is what makes the render 5.65x faster.

2.3 Two operational traps that have already cost work

Do not refresh the browser tab after translating. A job's translated text lives in the browser page, not on the box: the reference job's database row has tracks: [] and zero translated fields, and all 156 stored segments are the Hindi source. Refreshing loses the translation and it has to be produced again (measured at 4.8 s per line, so about 12 minutes for 156 lines).
The render reuses an existing per-line wav. dub_generate.py checks os.path.exists(seg_wav_path) and calls torchaudio.load on it rather than regenerating. So stale clips in a job directory are silently shipped. If lines have been rendered from text you no longer want, move them aside before rendering again: 
cd /root/.omnivoice/dub_jobs/<job>
for f in seg_te_*.wav; do mv "$f" "$f.parked.$(date -u +%Y%m%d%H%M%S)"; done
Keep seg_ref_*.wav and voice_speaker_*.wav: those derive from the source audio, not from any translation, and reusing them saves several minutes.

2.4 Never restart the app mid-render

Module defaults are read once at import time, so changing one requires an app reload to take effect — and a reload during a render abandons the job and leaves half-written segment files. Every revert script in section 9 checks for a render in flight and refuses to run if it finds one. Do the same by hand.

3. The pipeline, stage by stage

Twelve stages run between an uploaded video and a delivered dub. For each: what it does, which module owns it, and the line it writes to the log so you can confirm it ran.

Stage 1 — Ingest and separation

The upload is demuxed to audio.wav (working rate) and audio_hq.wav. HTDemucs 4.1.0 separates the mix into vocals.wav and no_vocals.wav. Scene cuts are detected and stored on the job. Everything downstream that looks at speech looks at the vocals stem, not the mix — that distinction is load-bearing: the same onset detector run on the mix is 268 ms wrong for English and costs 10.7 points of bench accuracy.

Stage 2 — Diarization

pyannote.audio 3.4.0 finds speaker turns; services/diar_unmerge.py splits over-merged speakers back apart (dominance 0.65, up to 8 speakers). The reference job resolved 7 speakers.

Stage 3 — Transcription

The transcript comes from Gemini 3.7 Flash reached over an OpenAI-compatible API at http://172.17.0.1:8900/v1 — a proxy on the Docker host, confirmed reachable (HTTP 200) from inside the container. The active backend class is OpenAICompatASRBackend. Audio is chunked at 120 s (OMNIVOICE_TRANSCRIBE_CHUNK_S) with 2 attempts per chunk and a 300 s per-chunk timeout.

INFO [omnivoice.asr] OpenAI-compat ASR transcribing ... model=gemini-3.7-flash

Stage 4 — Word times from Chirp 3

services/chirp_timing.py asks Google Speech-to-Text v2 for word-level timings. Two facts about this were established the hard way and are now encoded in the module:

  • chirp_3 is served only from the us and eu multi-regions. chirp_2 is served only from us-central1, europe-west4 and asia-southeast1. They share no location, so the location has to be chosen per model — that is what MODEL_LOCATION is.
  • chirp_3 rejects enableWordConfidence with HTTP 400 "Config contains unsupported fields". Sending word time offsets alone returns fully timed words in all seven target languages. Google's documentation saying chirp_3 has no word timestamps is wrong.

Audio is cut into 55 s chunks, boundaries moved into silence rather than cutting mid-word, 6 chunks in parallel. A chunk that returns 400/403/404 is retried once on chirp_2; a 5xx is not retried, because that is a bad moment rather than a bad model and retrying would bill twice.

INFO [omnivoice.chirp_timing] chirp: chirp_3 hi-IN -> 525 word(s) over 184s in 4 chunk(s)

Consequence to remember: chirp_3 returns no per-word confidence at all, so any threshold keyed on asr_confidence is inert.

Stage 5 — Line assembly, repair and gap recovery

services/chirp_wire.py is the orchestrator. It maps the transcript onto the word stream, tries four (pause, max-length, snap) grid points and keeps the best, folds slivers into neighbours, collapses repetition runs, and then recovers gaps — stretches of speech with no line over them — by re-asking the recogniser and positioning the words by forced alignment.

chirp: kept the start pause 0.80s max 12s snap 0.5

chirp: recovered 67 line(s) over 70 gap(s); speech coverage 72.4% -> 82.7%

Stage 6 — Forced alignment as the primary timing source

services/fa_timing.py. This is the change that matters most for timing. Previously Chirp gave the position and alignment only nudged it inside a narrow pad. Now alignment decides where a line sits, in a window bounded by trusted neighbours, and Chirp's position is not consulted. Three passes:

  1. Anchors. Each line is aligned in a narrow pad around its Chirp span. A line scoring at least 0.60 median per-word confidence, and moving no more than 2.0 s, becomes an anchor. Anchors never place a line; they only bound windows and feed the drift line.
  2. The wide pass. Each line is aligned in [previous accepted end − 1.5 s, cursor + max(8 s, 1.6 x line length)], further bounded by the next anchor. Only the line's length comes from Chirp, to keep the window finite.
  3. The drift guard. A Theil-Sen line (median of pairwise slopes, then median intercept) is fitted to the anchors' aligned starts against line index. Any run of 3 or more consecutive lines whose residuals share a sign and exceed 1.5 s and which also disagree with Chirp by more than 1.0 s is reverted to Chirp's times.

A line the aligner will not speak to comes back exactly as it arrived. Refusal reasons are counted and logged: window edge, length, backwards, from chirp, conf, collapsed, drift.

fa: source=fa_then_chirp 129 block(s) -> 18 placed by wide alignment, 12 by the hinted
    fallback, 99 kept chirp's times; 35 anchor(s)
fa: refusals by reason: {'length': 17, 'backwards': 37, 'drift': 33, 'window': 5, 'conf': 6}

Theil-Sen was chosen over least squares deliberately: the thing being guarded against is exactly the handful of far-off points that least squares would chase.

Stage 7 — Speaker split into rendered parts

Merged blocks are cut into speaker-pure parts — the lines that actually render. This is why two different counts appear in the logs and both are correct: the reference job was 129 blocks becoming 156 parts. The per-part quality metric exists because the pipeline used to score only blocks, which flattered it: one job reported 88.5% on 26 blocks while its 31 rendered lines scored 53.3%.

chirp: 129 block(s) cut into 156 speaker-pure part(s); part purity 100.0% (0 mixed)
chirp: placement per BLOCK well 76.7% badly 14.0% (129); per rendered PART well 68.6% (156)

Stage 8 — Timeline resolve

aligner.resolve_timeline. Overlaps are resolved by trimming the earlier line's end, not by moving the later line's start. The reason is ITU-R BT.1359-1: audio leading the picture is detectable at about 45 ms, lagging at about 125 ms, so a start time is the expensive thing to disturb and an end time is cheap. Only when trimming would leave the earlier line under 0.30 s is the later line pushed instead. A 0.02 s guard is left between lines.

aligner: timeline resolved - 156 line(s), 0 moved, 13 overlap(s) trimmed, 3 pushed;
         reversed 0, out-of-order 0, still overlapping 0

Stage 9 — Onset snap

chirp_wire._snap_onsets, run on the vocals stem after resolve and before breathe. It moves a line's start onto the real speech onset: backwards up to 0.60 s to recover a clipped lead-in, or forwards to trim dead air. The voiced gate is band-limited to 300–3400 Hz, zero-phase (a causal filter would delay every onset by its own group delay, which is the thing being measured). A 0.05 s guard stops a start ever landing inside the previous line's span.

chirp: onset snap moved 36 start(s) back (14.1s of lead-in recovered) and 13 forward
       (2.5s of dead air trimmed)

Stage 10 — Breathe

Each line's end is extended toward the next line's onset by at most 0.30 s. Starts are never touched. The cap exists because an uncapped version added 135.4 s across 63 lines on a 96-part job; the underrun fill then stretched every one of those lines to fill the slot, clamped at 0.85x, and the whole dub played 15% slow and drifted against the picture.

aligner: extended 112 line(s) into the pause after them, recovering 28.2s of speaking
         room (no start times changed)

Stage 11 — Voice cloning

services/speaker_clone.py builds one reference per speaker by assembling clean, properly-spoken slices (ideal 8 s, minimum 5 s, maximum 15 s), and then per-line references where a line can serve as its own. The reference job got 7 of 7 speakers cloned and 142 of 156 lines with their own reference (91%), after widening the window for 72 short lines. Non-speech is rejected outright rather than merely ranked lower — one speaker's candidate slices were laughter and were refused.

speaker voices: 7 of 7 speaker(s) cloned from the video
segment refs: 142 of 156 line(s) have a reference of their own (91%) - was 45%
speaker_clone: Speaker 6 cloned from the 'clean, properly spoken' assembly, score 0.845
vocal_events: Speaker 2 - 1 of 2 candidate slice(s) are not speech; REJECTED

Stage 12 — Render, start-on-time, watermark, mix

Per line: TTS generates the clip, head_language.front_silence removes the clip's own leading near-silence so the first syllable lands on the slot start (pure local numpy — an RMS envelope, a run-length test, and a verify-then-walk-back loop that guarantees only audio at least 20 dB below the clip's own speech level is removed), AudioSeal 0.2.0 watermarks it, and the clip is mixed against the retained backing track.

start on time: c122 began 0.09s late, moved onto its slot
bench[generate] total=445.28s tts=369.92s cache=0.00s diskw=0.02s mix=2.08s segs=156
What is NOT in this stage any more. Between TTS and start-on-time there used to be a per-line call to the remote recogniser that checked whether the generated clip opened in the wrong language. It is off. See sections 7.5 and 10.1.

5. Environment flag quick reference

The backend reads 294 distinct OMNIVOICE_* flags. The container's environment sets only three of them, so everything else is a module default. docker exec -e OMNIVOICE_SNAP_BRIDGE=1 <container> ...
The container's environment is fixed at create time. It holds OMNIVOICE_SERVER_MODE=1, HF_HOME and HF_TOKEN and nothing else. 7. What changed on 2026-08-21, and what each change bought

Five changes were deployed. Each was measured against its own baseline before shipping, each has a named off switch, and each has a revert script. The bench figures are not additive; section 6 gives the combined as-deployed number.

7.1 Chirp 2 → Chirp 3 (services/chirp_timing.py)

Per-model location, and enableWordConfidence dropped. The recorded 403 that had made chirp_3 look unavailable was our own bug, twice over. Works in all seven languages. Cost: on the real video, chirp_3 with the old hinted re-anchor scored 72.1% against chirp_2's 78.4%, and coverage fell 87.8→85.3%. It also returns no per-word confidence at all. Forced alignment (7.2) is what recovers the placement loss.
Off switch: OMNIVOICE_CHIRP_MODEL=chirp_2. Revert: revert_fa.ps1 -Level chirp3.

7.2 Forced alignment as the primary timing source (new services/fa_timing.py)

+16.6 bench points over chirp_3's own word times, better on 13 of 14 conditions and tied on the 14th. On the real video 72.1→76.3 well placed and 16.4→12.2 badly placed on the same chirp_3 word times. p95 tails fell in 11 of 14 conditions.
Off switch: OMNIVOICE_TIMING_SOURCE=chirp. Revert: revert_fa.ps1 -Level fa.

7.3 The per_line window-split bug fix (services/aligner.py)

A real bug: align_window returns one entry per word it kept, but the split back onto lines used each line's original word count. One dropped word — a bare numeral, (2), 11:35 — handed every later line in that window the wrong words. Worth +15.0 points through retime_segments on a production-shaped 45 s window and +30.5 on a whole-file window.

Stated plainly: retime_segments currently has no caller in the live tree, so the production effect today is zero. It was shipped because any future re-anchor experiment now starts from a correct split instead of a 15-to-30 point hole. The bench proves it changes nothing on the live path: identical cell for cell, refusal for refusal.

The fix was chosen over the alternative (a placeholder entry) after auditing all seven call sites: four of them would have acted on a placeholder, so that "bug fix" would have been a change to the whole timing stage in disguise.

7.4 MMS star tokens (services/aligner.py)

Bench 66.8→68.8 on the shipped cascade. The mechanism is visible in the refusal histogram: edge dumping stops, so backwards falls 44→2, window 5→0, and 58 more lines get placed by alignment. Honest size: net 11 lines of 560, with four conditions losing 2.5 points each.
Off switch: OMNIVOICE_ALIGN_STARS=0.

7.5 Band-limited onset gate, and the leak check switched off (services/chirp_wire.py, services/head_language.py)

Band gate: +15.5 bench points over the broadband gate, wins or ties all 14 conditions, halves the moves, zero crossings. Shipped on.

Leak check off: median 13.77→2.44 s per line, 5.65x. Zero network calls in the render, asserted at the socket layer with a positive control. This one trades a safeguard for speed and should be understood as such — see 10.1.

8. The invariants — never break these

Two numbers protect earlier clean-audio work that must not be disturbed. Check them before and after every change, and again at the end. If either is wrong, do not render until it is understood. 
docker exec CT grep -cE 'lead_in|leadin|sibilant|_LEAD_IN' /app/backend/api/routers/dub_generate.py
   -> must be 5

docker exec CT stat -c %s /app/backend/services/speech_rate.py
   -> must be 13073

The marker count is a checksum on intent, not just on text: any new identifier containing the substring leadin inflates it. When working on onset or lead-in code, name things onset, snap, run, bridge. Every patch script in this project greps the patched source for the substring and refuses to write if the count changes — that guard has fired for real, on a comment containing the word "leading".

10.7 A note on English specifically

English sits lowest but one on placement (62.5% bench mean) and the cause is understood precisely. It is not the ground truth, the word mapping, the search window, or the orthography — all four were tested and eliminated. On 7–8 of 40 lines the aligner abandons a sentence-initial monosyllable followed by a pause ("The…", "But…", "As…"), parking its letters in an 80–120 ms sliver just before the second word and leaving the 0.4–0.9 s where the word was actually spoken outside the line. It splits cleanly by speaker: within the English corpus the male readers are the slow ones (0.399 s per word against 0.281 s), and slow delivery is what leaves a lengthened leading monosyllable for CTC to skip.

The fix exists and is one flag away: OMNIVOICE_SNAP_BRIDGE=1 takes English from 62.5 to 80.0 on the bench, recovers 7 of the 8 affected lines including an 878 ms case the 600 ms cap could not reach, and introduced zero previous-line crossings in 479 moved starts. It is off by default only because it costs the other six languages 7.7 points. Turn it on for English-primary jobs.

13. Working practices that prevented mistakes

These are not style preferences. Each one is here because skipping it produced a wrong answer that had to be found and undone.

13.1 Measurement discipline

  • Measure before fixing, and test after. Of roughly a dozen plausible fixes attempted on this pipeline, six were refuted by their own measurement. Reporting those honestly was worth more than shipping them.
  • Never judge a change with a detector you just weakened. The circular measurement in 10.2 is the canonical example.
  • Report median and p95, never the mean alone. A mean of 11,685 ms once hid behind a median of 30 ms — a handful of lines dragging a whole tail.
  • Reproduce the baseline before believing the arm. Every harness in this project first reproduces a known column cell for cell. If the baseline does not reproduce, the harness is measuring something else and the new number is worthless.
  • Know the standard error. At n=139 parts, one standard error on a 76% proportion is 3.6 points. A 2-point move is not a win.
  • One GPU arm at a time. A measurement that overlapped another GPU job came back with 116 blocks instead of 118 and a different refusal histogram, and had to be thrown away. Another returned "100% everywhere, everything kept" in 1 s per condition — which is what a silently disabled aligner looks like.
  • Pin what you measure against. Files were being patched in parallel; snapshotting the modules and importing the snapshot is the only reason several results are still trustworthy.

13.2 Patching a running container safely

  • Back up first to f.pre<tag>.<utc>.
  • Assert every patch anchor occurs exactly once in the live file, read off the box with its real indentation. Never reconstruct an anchor from memory. Abort and restore if the count is not 1.
  • py_compile is not enough. Import every touched module for real. A missing import os once silently disabled a whole module.
  • Judge import main by its exit code, not by whether it printed — it logs to stderr even when healthy. An over-strict version of that check rolled back a good patch.
  • Re-check the invariants before and after every write.
  • Reload the app after changing a default, because defaults are read at import time — but never mid-render.
  • Every feature needs a revert script on the established pattern: .prerevert.<utc> backup, real imports, invariant re-check, app reload with /sysinfo confirmed, refusal to run mid-render, and both -Status and -WhatIf.
